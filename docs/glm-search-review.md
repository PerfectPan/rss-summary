# GLM 混合搜索效果评审

> 本文保留对初始提交 `80428cf` 的评审依据；后续已实现的行为和剩余限制以 [接入说明](./glm-search.md) 为准。

评审日期：2026-09-29。对象：PR #52，提交 `80428cf`。仅采集，不投递消息、不修改运行时配置。

## 判断

当前 GLM Search 不建议启用到定时新闻简报。Reader 可作为已知文章链接的备用读取通道，但这次只验证了两个官网页面。接口成功和自动化测试通过不能代替搜索效果验收。

## 本轮样本

共 13 次真实 Search 请求、2 次 Reader 请求，使用现有 Coding Plan MCP。

| 样本 | 观察 | 判断 |
| --- | --- | --- |
| 当前配置的 7 条主题查询，oneDay | 7 条查询经域名校验后均为 0 个候选 | 本轮没有新增可用新闻；没有当天完整新闻真值集，不能计算真实召回率 |
| TypeScript 单官网查询，oneDay | 0 个候选 | 缩小来源也未在本轮找回近期文章 |
| 精确 TypeScript 6.0 查询，noLimit，重复 2 次 | 两次均返回标题 Announcing TypeScript 5.5 RC、链接 devblogs.microsoft.com 首页 | 版本错误且不能定位文章，2 次均不可用 |
| Anthropic 单官网查询，noLimit | 1 个带文章标题的结果，链接为 anthropic.com 首页 | 无法作为文章证据入选 |
| 当前模型发布查询，oneDay / noLimit 对照 | 各返回 3 条原始结果；均为白名单外站点且链接为站点根地址 | 这两次在搜索/来源阶段就失败，并非被发布时间规则误杀 |
| Reader 读取 TypeScript 6.0 原文 | 正文达到 16000 字符上限，发布时间 2026-03-23T16:34:10Z | 明确链接可读；该文为历史文章，不可当作今日新闻 |
| Reader 读取 Sonnet 4.6 原文 | 15058 字符，发布时间 2026-02-17T18:00:00Z | 明确链接可读；同样不是今日新闻 |

本轮搜索请求耗时约 1.5–3.9 秒，主要问题是结果可用性，不是响应速度。先前测试曾找到 TypeScript 精确文章，但本轮重复两次未复现，因此不能将一次命中当作稳定质量。

Reader 样本由独立网页检索提供确定链接，不能计入 GLM Search 成功率。前 10 次采样只采用客户端输出计数，原始响应捕获未正确处理 SSE 前缀；随后 3 次控制组修正采样后核验原始响应。没有把缺失的原始采样记为服务端空结果。

## 当前实现会进一步限制覆盖

1. `src/infrastructure/glm-research.ts` 仅在一个域名时发送服务端 `search_domain_filter`；`news-topics.json` 的七条配置均为多个域名。当前生产查询实际先全网搜索，再本地按域名丢弃，并不是在这些官网内分别检索。
2. `src/application/hybrid-news-search.ts` 按顺序消耗预算，默认搜索上限为 4。豆包持续耗尽且前四条均进入补查时，后面的开源安全、政策和资本三条没有 GLM 搜索机会。
3. 严格时间和来源筛选有必要；不能为了提高入选数量，把首页当文章，或用抓取时间代替发布时间。后续应先修复候选发现质量，再独立验证关键词和时间筛选的漏报率。

## 建议

- 保持 `NEWS_SEARCH_MODE=doubao`，暂不启用混合搜索。
- 保留 Reader 可选能力，先用于已知原文链接读取失败的补救。
- 若继续开发 Search，先做单实体、单站点查询对照和所有主题的预算覆盖，再用已知文章集合测量可定位原文比例、主题准确性、时间正确性与两源新增覆盖。
- 豆包此前返回免费额度耗尽，本轮未反复消耗请求重试，因此不宣称 GLM 比豆包更差或更好；这里只判定当前 GLM 接入未达到生产效果要求。

## 优化后的复测

同日将查询改为单来源、单实体，并预留每个主题查询的预算后，以 7 次搜索和 7 次 Reader 上限跑完全部 7 个主题查询：

- `noLimit` 对照返回 28 条原始候选，全部未通过对应请求的域名校验。
- 核对在线 MCP `tools/list`，确认域名参数名、类型和 `location`、`oneWeek` 均与接口定义一致；检查原始工具响应，确认精确 TypeScript 查询的 `link` 本身就是官网首页，没有被本地解析截短。
- 最终方案采用近一周及目标地区参数，再跑 7 次搜索，返回 30 条原始候选，其中 28 条被域名校验丢弃；2 条进入可读候选，预算内读取 1 篇，缺少通过核验的原文信息，另 1 篇未读。最终 0 条入选。
- 最终结果是 `partial`，正常报告覆盖不完整，未伪称没有新闻或备用已成功恢复。所有主题都有实际请求，未发生固定后三类被跳过。

这些结果验证了本地调用、预算和诊断行为，仍未证明 GLM 可以增加合格新闻覆盖。保持默认豆包模式，GLM 仅显式启用；不能因为修好了本地逻辑就宣称搜索服务效果合格。

## 官网假设的纠正

上面的域名淘汰数字反映的是当时的官网白名单规则，不证明被过滤的媒体结果质量差。默认新闻模式已移除提供方域名/官方认证限制及本地官网门槛，允许媒体报道进入原文核验；错误链接、过期与不相关内容仍分别检查。已知一手来源用于排序加分，网页读取成功不代表来源已经获认证。
